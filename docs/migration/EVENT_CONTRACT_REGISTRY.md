# Event contract registry

Use the [83-name accepted event inventory](realtime-event-inventory.md) for the DCR-3 catalog and review new events against source. The refreshed [socket registration inventory](../production/socket-inventory.csv) contains 11 statically found `socket` and `io` registration expressions. It covers a narrower set than the catalog because outgoing events, dynamic names and Android listeners have other sources.

| Contract surface | Authority | Parity to demonstrate |
| --- | --- | --- |
| Socket names and delivery scope | [Shared event names](../../backend-server/packages/shared/src/index.ts), [Socket.IO handlers and emitters](../../backend-server/apps/api/src/services/socket.ts) | Validate actual handler payload, auth, ack, recipients, ordering and error path. |
| Messaging and rooms | [Messages](../../backend-server/apps/api/src/routes/users.ts), [clans](../../backend-server/apps/api/src/routes/groups.ts), [rooms](../../backend-server/apps/api/src/routes/rooms.ts), [Android listeners](../../android-client/core/api/src/main/java/com/yugm/app/core/api/SocketManager.kt) | The [DM fixture](../../backend-server/apps/api/src/routes/directMessages.characterization.test.ts) captures new-message fan-out to both participants and the explicit read receipt plus reader self-echo. Native compatibility, reconnect recovery, multi-session sync and other message/room events remain open. |
| PK and invalidation | [PK events](../../backend-server/apps/api/src/services/pk.ts), [sync invalidation middleware](../../backend-server/apps/api/src/middleware/syncInvalidation.ts) | Verify timing and publication ordering after authoritative commit. Check `BONDS` and other topic consumers against real legacy and native paths. |
| Notifications | [Persistence and dispatch](../../backend-server/apps/api/src/services/notifications.ts), [job delivery code](../../backend-server/apps/api/src/services/jobs.ts) | Preserve target, trigger, payload and recipient conditions across the inbox, socket and FCM channels. |
| Native and compatibility paths | [Protocol](../../backend-server/packages/shared/src/realtimeProtocol.ts), [legacy adapter](../../backend-server/packages/shared/src/legacyRealtimeAdapter.ts), [parity matrix](../../backend-server/packages/shared/src/realtimeParity.ts) | These harnesses provide reusable scenarios. Wire both paths and measure reconnect, duplicates, replay, acknowledgements and legacy support before claiming interoperability. |

For each affected inbound/outbound event capture name and version, sender and recipient scope, payload, success/rejection semantics, ordering, replay and dedupe, and client effect. Unknown semantics stay open. The [staged hybrid decision](../decisions/0002-staged-hybrid-realtime-protocol.md) preserves the 90-day window from native GA.
