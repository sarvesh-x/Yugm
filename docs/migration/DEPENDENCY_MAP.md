# Infrastructure dependency map

Keep one verified transition per dependency. Leave legacy paths available until the replacement owns its approved traffic with tested behavior and rollback. [Detailed source audit](DEPENDENCY_AUDIT.md)

| Dependency | Current source boundary | Proposed replacement and acceptance |
| --- | --- | --- |
| Render / Node hosting | [Node entry point](../../backend-server/apps/api/src/index.ts), [Worker entry](../../backend-server/apps/cloudflare-worker/src/index.ts), [staging runtime](../../backend-server/apps/cloudflare-worker/src/runtime.ts) | Workers behind established API contracts. Confirm actual deployment inventory before retiring hosting. Compare response/error behavior, scheduled jobs and live readiness. |
| MongoDB / Mongoose | [Connection](../../backend-server/apps/api/src/config/db.ts), [model contracts](MODEL_CONTRACT_REGISTRY.md) | D1 repositories behind existing behavior. Validate Free capacity, exact field representations, transactions, source/import reconciliation and restore. |
| Redis | [Client](../../backend-server/apps/api/src/services/redis.ts), [rate limit](../../backend-server/apps/api/src/middleware/rateLimit.ts), [socket adapter](../../backend-server/apps/api/src/services/socket.ts) | SQLite Durable Objects for consistent coordination, KV for staleness-tolerant cache, queues for delivery. Inventory each caller and preserve expiry, counter semantics and readiness/fallback. |
| BullMQ and periodic work | [Jobs](../../backend-server/apps/api/src/services/jobs.ts), [notification dispatch](../../backend-server/apps/api/src/services/notifications.ts), [Worker alarms](../../backend-server/apps/cloudflare-worker/src/index.ts) | [Opt-in local push queue](../handoffs/2026-11-23-local-push-queues.md) uses a SQLite Durable Object outbox with notification IDs, terminal states, alarms and retries. Verify staging Firebase delivery, quota fit and queue drain before any provider switch. Existing periodic jobs keep their current scheduling. |
| Socket.IO | [Server](../../backend-server/apps/api/src/services/socket.ts), [Android client](../../android-client/core/api/src/main/java/com/yugm/app/core/api/SocketManager.kt) | Hibernating resource-scoped Durable Objects and versioned compatibility under [DCR-3](../decisions/0002-staged-hybrid-realtime-protocol.md). Both wire paths remain gated by behavior and existing-client support. |
| LiveKit | [RTC service](../../backend-server/apps/api/src/services/livekit.ts), [Android media](../../android-client/core/api/src/main/java/com/yugm/app/core/api/YugmMediaRoom.kt) | SFU/TURN behind an RTC provider boundary. Match Android room, media and network-recovery behavior. Bound free usage before activating. |
| Filesystem, legacy media and S3-compatible calls | [Storage selection](../../backend-server/apps/api/src/services/storage.ts), [media](../../backend-server/apps/api/src/services/media.ts), [R2 interface](../../backend-server/apps/api/src/services/r2.ts) | R2 Standard with a tested zero-spend admission path, category inventory and private access. Preserve existing references and recoverability. |
| Sharp and incompatible Node libraries | [Node image provider](../../backend-server/apps/api/src/services/imageProcessor.node.ts), [Worker Images provider](../../backend-server/apps/cloudflare-worker/src/imageProcessor.ts) | The existing host-neutral registry keeps Sharp out of the Worker. Retest bundle and image behavior after further changes. Keep Node implementation for supported local paths until separately retired. |
| Firebase Auth, App Check and FCM | [Firebase service](../../backend-server/apps/api/src/services/firebase.ts), [App Check](../../backend-server/apps/api/src/middleware/appCheck.ts), [auth routes](../../backend-server/apps/api/src/routes/auth.ts) | Retain Firebase identities, verification, supported sign-in flows and push. Validate on Worker and Android without requiring re-registration or a new paid plan. |
| Payment integrations | [Wallet routes](../../backend-server/apps/api/src/routes/wallet.ts), [subscription routes](../../backend-server/apps/api/src/routes/subscriptions.ts), [purchase credit](../../backend-server/apps/api/src/services/purchaseCredit.ts), [Android wallet](../../android-client/feature/wallet) | Preserve existing integrations, payout and provider-webhook accounting behavior. Changes to payment features or new charges require separate approval. |

Provider capacity and billing evidence belongs in the [active migration plan](implementation-plan.md). A metered replacement whose zero-spend operation remains unproven stays out of production. An existing feature remains on its verified legacy path until an equivalent approved replacement is available.
