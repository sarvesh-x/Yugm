# API contract registry

The current [mounted HTTP inventory](../production/endpoint-inventory.csv) indexes 624 statically discovered entries with route source, registration line and middleware. Multiple mounts can produce multiple entries for one source handler. The scanner misses dynamic or nested registrations and leaves unresolved mounts and resource/operation checks open. [Source extractor](../../backend-server/scripts/production-inventory.cjs)

Use the [Express mount and error handling](../../backend-server/apps/api/src/app.ts), [OpenAPI](../../backend-server/apps/api/openapi.yaml), [shared schemas](../../backend-server/packages/shared/src/index.ts), [Android API interfaces and DTOs](../../android-client/core/api), and [admin consumers](../../backend-server/apps/admin/src) to verify each affected contract. When documents and runtime differ, characterize the actual response and record which behavior consumers depend on before deciding whether there is a bug.

For each ported operation pin method, path, request/response and error shapes, status, pagination, filters, sort order, auth, resource auth, idempotency and side effects. Compare legacy and replacement using the same fixtures. Preserve differences intentionally required by versioned clients under the existing compatibility gate.
