# Business rule registry

Rules below are preservation checkpoints from named implementations. Expand each affected row into executable cases before changing its adapter. A discrepancy between source, tests and a behavioral specification stays open until its intended outcome is established.

| Domain | Rule to characterize | Authority and existing evidence |
| --- | --- | --- |
| Account and profile | Keep Firebase UID, user ID, verified sign-in requirements, restrictions and session rotation/revocation. First Profile completion records consent and completion and grants XP once. Keep wallet changes server-owned and derive relationship counts from their source rows. | [Auth routes](../../backend-server/apps/api/src/routes/auth.ts) · [Session guard](../../backend-server/apps/api/src/middleware/auth.ts) · [Profile HTTP fixture](../handoffs/2026-11-24-profile-contract-baseline.md) · [Local D1 completion and rollback](../handoffs/2026-11-24-d1-profile-edits.md) |
| Wallet and purchase | Server determines amounts and eligibility. Balance and ledger effects belong to one atomic operation. Preserve history, ownership, idempotency, failure and refund behavior. | [Wallet](../../backend-server/apps/api/src/services/wallet.ts), [purchase credit](../../backend-server/apps/api/src/services/purchaseCredit.ts), [ledger contract](../wallet-ledger.md) |
| Gifts | Preserve sender authorization, recipient and room constraints, debit/ownership outcomes and event/notification order. Denied combo or trade requests must leave state untouched. | [Gift service](../../backend-server/apps/api/src/services/gifts.ts), [authorization fixtures](../../backend-server/apps/api/src/services/giftAuthorization.test.ts), [replay fixtures](../../backend-server/apps/api/src/services/giftReplay.test.ts) |
| Cosmetics and store | Keep price and availability decisions server-side. Preserve owned/equipped items, expiry, grant source, publication version and game/client-visible renderer configuration. | [Cosmetics](../../backend-server/apps/api/src/services/cosmetics.ts), [admin cosmetics](../../backend-server/apps/api/src/routes/adminCosmetics.ts), [ecosystem audit](../features/cosmetics-ecosystem-audit.md) |
| Achievements, missions and rewards | Preserve criteria, tier, quantity, progress and grant timing. A repeat evaluation should follow the existing grant identity and idempotency semantics. | [Experience routes](../../backend-server/apps/api/src/routes/experience.ts), [badges](../../backend-server/apps/api/src/services/badges.ts), [badge tests](../../backend-server/apps/api/src/services/badges.test.ts), [missions](../../backend-server/apps/api/src/routes/missions.ts) |
| Social, friends, Bonds and dating | Preserve eligibility, request/accept lifecycle, relationship limits, blocking and visibility rules. | [Friends](../../backend-server/apps/api/src/routes/friends.ts), [Bonds](../../backend-server/apps/api/src/services/bonds.ts), [dating](../../backend-server/apps/api/src/routes/dating.ts), [Bonds contract](../bonds.md) |
| DM and clan chat | Preserve membership, blocked/hidden behavior, history, ordering, unread state and receipt recipients. The legacy DM route assigns a new message ID to each accepted HTTP send, even for matching text. XP grant keys are per persisted message. Keep this distinct from retrying a native command with the same identity. Clan and end-to-end transport parity remain open. | [User routes](../../backend-server/apps/api/src/routes/users.ts), [groups](../../backend-server/apps/api/src/routes/groups.ts), [socket handlers](../../backend-server/apps/api/src/services/socket.ts), [DM fixture](../../backend-server/apps/api/src/routes/directMessages.characterization.test.ts) |
| Rooms and PK | Preserve join restrictions, seat and host permissions, official-room lifecycle, deadline processing, score, settlement and event ordering. Keep RTC media behavior and room state separately testable. | [Rooms](../../backend-server/apps/api/src/routes/rooms.ts), [room lifecycle](../../backend-server/apps/api/src/services/roomLifecycle.ts), [PK service](../../backend-server/apps/api/src/services/pk.ts), [PK tests](../../backend-server/apps/api/src/services/pk.test.ts) |
| Game scoring | Preserve accepted IDs and score/activity checks, rank and tie ordering, recent history, XP and challenge side effects. The first fixture establishes the signed-in catalog read contract. | [Games routes](../../backend-server/apps/api/src/routes/games.ts), [score schema](../../backend-server/apps/api/src/models/MiniGameScore.ts), [catalog fixture](../../backend-server/apps/api/src/routes/gamesCatalog.characterization.test.ts) |
| Notifications | Persist the in-app record before dispatch. Message and marketing opt-out suppress socket and push, while Bonds push opt-out preserves socket fan-out. Provider failure leaves the inbox intact. Verify retries, partial failures and dedupe separately from the notification record. | [Dispatch](../../backend-server/apps/api/src/services/notifications.ts), [FCM](../../backend-server/apps/api/src/services/firebase.ts), [characterization](../../backend-server/apps/api/src/services/notifications.characterization.test.ts) |
| Media | Preserve current avatar until a new commit, media ownership, private access, resource scopes, references and version visibility. | [Media service](../../backend-server/apps/api/src/services/media.ts), [access policy](../../backend-server/apps/api/src/services/mediaAccessPolicy.ts), [HTTP integration tests](../../backend-server/apps/api/src/services/media.routes.integration.test.ts) |
| Admin and safety | Preserve role and permission checks on each action, resource visibility, audit records, and separation of moderation, identity trust and creator payout policy. | [Admin auth](../../backend-server/apps/api/src/middleware/adminAuth.ts), [admin routes](../../backend-server/apps/api/src/routes/admin.ts), [moderation workflow](../moderation-workflow.md), [creator payout KYC](../creator-payout-kyc.md) |

For each characterization case record fixture, request or action, response or screen outcome, persisted changes, event and notification effects, ordering, denial and retry. Repeat the same cases against the replacement where applicable. The table is an index of rule owners and current evidence. It does not establish completed coverage.
