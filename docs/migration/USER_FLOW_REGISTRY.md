# User flow registry

**Baseline:** Existing Android and admin entry points mapped to the server boundaries below. These are the required legacy-versus-Cloudflare scenarios. Arcade catalog parity and the direct-message HTTP baseline have local fixtures. Device journeys and broader replacement parity remain open.

The [navigation graph](../../android-client/app/src/main/java/com/yugm/app/navigation/NavGraph.kt) and [navigation standard](../NAVIGATION_ARCHITECTURE.md) govern the five roots, dock, back stack and inset ownership. For each scenario capture actual entry, screens, loading and empty states, permitted and denied actions, success destination, errors, retries, persistence, live effects and process/reconnect behavior.

Use the [journey order](implementation-plan.md#journey-order) to select work. The numbered scenarios below are verification cases for their owning journeys.
