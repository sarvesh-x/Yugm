# Per-feature Cloudflare migration matrix

**Date:** 2026-11-22  
**Status:** Phase 0 matrix. All four source audits (backend, Android, admin/infrastructure, Worker prototype) are reconciled. Statuses are evidence-based, not runtime-verified; see the [backend audit](../architecture/backend-source-audit.md) and [Android audit](../architecture/android-source-audit.md).

## How to read this matrix

- **Current state** uses existing project vocabulary from [the feature registry](../FEATURE_REGISTRY.md). `Implemented but unverified` means source exists and unit/integration evidence may exist, but live end-to-end behavior is not proven.
- Path prefixes: `api/` = `backend-server/apps/api/src/`, `client/` = `android-client/`, `admin/` = `backend-server/apps/admin/src/`.
- Existing HTTP/Socket/schema inventories are historical generated evidence, not live truth. Current API behavior must be read from source and OpenAPI; see [API contracts](../API_CONTRACTS.md) and [realtime contracts](../REALTIME_EVENTS.md).
- No migration changes have been applied. "Target change" describes work in [the implementation plan](implementation-plan.md), not work already done.
- Client-specific findings come from the [Android source audit](../architecture/android-source-audit.md); admin findings from the [admin/deployment audit](../infrastructure/admin-deployment-audit.md).

## Cross-feature preservation checklist

Every phase must verify preservation of:

- Accounts, Firebase identifiers, session families and device tokens.
- Coin/diamond balances, append-only transaction history, purchases, refunds and payouts.
- Ownership, equipped cosmetics, worn badges, gifts, achievements, expirations and reward history.
- Bonds, friendships, clans, blocks, bans, moderation history and support tickets.
- Message history, room memberships, recordings and media references.
- Asset/media versions, prior versions, visibility, moderation state and checksums.
- Admin users, roles, permissions, 2FA state and audit logs.
- UTC timestamps, integer currency units and user-visible IDs.

## Open per-feature decisions

1. D1 versus PostgreSQL/Hyperdrive before any schema is generated.
2. Socket.IO compatibility adapter versus versioned native DO protocol.
3. R2 bucket/domain/CORS ownership and which legacy media URLs must be reconciled.
4. Room/clan private-media participant rules.
5. Badge legacy `imageData` cleanup and multipart upload retirement.
6. Admin bulk-PII read auditing and global versus high-value-only 2FA enforcement.
