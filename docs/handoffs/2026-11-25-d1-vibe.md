## Preserved behavior

- Router-scoped authentication runs before `validateBody`, matching the legacy `vibeRouter.use(requireAuth)`. Unauthenticated requests return `401`; invalid bodies return `422` only after a valid session.
- `init` copies the user's ordered interests, languages and city into a new graph and returns `201`; repeat calls return `200` with the same graph.
- `update` keeps the legacy point table (`message` 2, `room_join` 3, `gift` 5, `room_host` 4, `story_reply` 2), the 0–100 score cap, interaction counter, response fields and ignored `targetUserId` compatibility calculation.
- `match/:userId` preserves ID validation order, the two 404 messages, score formula, label thresholds, shared-interest/language lists, case-insensitive city comparison and limited target-user DTO.
- `matches` filters by the current user's interests only, oversamples by five, sorts by score, caps `limit` at 50 and applies legacy defaults. Legacy `parseInt` behavior is preserved for malformed page/limit values: `NaN` is treated as unbounded with zero skip.
- `preferences` preserves the Mongoose upsert observed with a disposable in-memory MongoDB: an undeclared `preferences` field is dropped, a new graph has score `0`, empty ordered lists, default city `""`, current `lastVibeUpdate` and timestamps; an existing graph has only `updatedAt` changed.

The ordered child tables are projected with `json_group_array(... ORDER BY position)` so responses retain array order. Candidate pagination orders by `users.created_at, users.source_id` to approximate the legacy natural insertion order for tied scores.
