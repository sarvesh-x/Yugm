# D1 creator payout-kyc and withdrawals

- **Date:** 2026-11-25
- **Slice:** Mount 7 legacy `/api/creator` routes on the shared D1 Worker.

## What changed

- Added `backend-server/apps/api/src/migration/d1Creator.ts` and mounted it in `backend-server/apps/api/src/migration/d1App.ts`.
- Wired `PAYOUT_KYC_ENCRYPTION_KEY` through `D1WalletConfig` and `apps/cloudflare-worker/src/d1Api.ts`.
- Routes: `GET /payout-kyc`, `GET /payout-kyc/status`, `PATCH /payout-kyc`, `POST /payout-kyc/submit`, `GET /withdrawals`, `GET /withdrawals/eligibility`, `POST /withdrawals`.
- Added basic creator fixture coverage in `apps/cloudflare-worker/test/d1-endpoints.mjs`.

## Behavior preserved

- Auth before validation; creator/host role gate on creator routes.
- Legacy KYC validation (adult DOB, PAN format, UPI/bank requirements, declarations) and status transitions to `PENDING`/`MANUAL_REVIEW` on submit/update.
- Sensitive KYC fields encrypted with node:crypto AES-256-GCM using `PAYOUT_KYC_ENCRYPTION_KEY`; only masked/last4 fields returned.
- Withdrawal eligibility checks: role, block/suspension, trust verified + creatorTrustEnabled, KYC verified + payout enabled, active withdrawal lock, available balance.
- Withdrawal creation computes balance, runs D1 fraud checks, creates withdrawal + payout review in a guarded D1 batch; conflicts on active withdrawal or insufficient balance.

## Boundaries

- D1 schema lacks Mongo partial unique indexes for `creator_payout_kycs.user_id` and active `withdrawal_requests` lock; code uses guarded checks/batch inserts but hosted schema/index audit may be needed for strict parity.
- No payout provider execution from creator routes; admin payout decisions remain the existing D1 admin flow.
- No new migration.
