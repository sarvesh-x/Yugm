# 2026-11-24 — D1 Bonds route group and maintenance

## Scope

Port the Bonds HTTP route group and Bonds maintenance to the local MongoDB-free D1 Worker while preserving the legacy contracts and business rules. Work stayed on `master`; all pre-existing staged/unstaged changes and untracked files were preserved. No commit, push, deploy, provision, migration against a hosted environment, credential rotation or production data operation was performed.

## Changes applied

- Added `backend-server/apps/api/src/migration/d1Bonds.ts` and mounted `createD1BondsRouter(db)` at `/api/bonds` in `d1App.ts`. All 16 audited Bonds method/path patterns are mounted.
- Extracted host-neutral rules from `services/bonds.ts` into `services/bondRulesCore.ts`; `bondRules.ts` re-exports them so the legacy service and Worker bundle share one source. No `mongoose`, `mongodb`, `sharp` or `livekit-server-sdk` import was added.
- Implemented Bonds eligibility and slot rules, invitation settings, paid invitation coin holds and idempotent releases, free invitations, acceptance, decline/cancel, replay keys, type-change requests, preferences, check-ins with reciprocal scoring, bond gifts with the 10% fee and daily caps, `/me`, `/:id`, profile, catalog, eligible-friend and leaderboard reads, and explicit end.
- Kept authoritative balances, receipts, points, preferences, milestones and pair state in D1. Guarded notifications, version bumps and wallet transactions are batched with the state changes that justify them.
- Added block termination through the existing `d1Social.ts` block hook and exported `endD1UnavailableBonds()` for later moderation/account-deletion wiring.
- Moved Bonds milestones, ranking snapshots, delayed rewards and held-request expiry into `runD1BondMaintenance()`. `d1Maintenance.ts` loads that module dynamically so `env.ts` is not pulled into the Worker static startup graph.
- Forwarded `YUGM_BONDS_ENABLED` and `YUGM_BOND_SLOTS` in the Worker runtime flags. The local debug config sets `YUGM_BONDS_ENABLED=true`; production/staging values were not changed and still need operator confirmation.
- Added and wired `backend-server/apps/cloudflare-worker/test/d1-bonds.mjs` into `auth-worker.mjs`. The fixture covers auth rejection, catalog, eligibility and invitation opt-out, replayed paid invitations, cancellation with one release, free acceptance, legacy detail DTO shape, preferences, reciprocal check-ins, gift fees/points/caps, public leaderboard, public profile, type change, explicit end and block termination.

Fixture-driven fixes made during this slice:

- The legacy person DTO always emits `username`, `avatar`, `avatarType` and `avatarParts`, with nulls where absent; details now use the same shape.
- Imported boolean preferences can be `1`/`0` in `value_json`; DTOs now normalize them to booleans.
- Check-in replay keys must use `bondPointId(bondId, key)` on both sides, otherwise the reciprocal bonus is missed.
- Paid invitation gift lookup must check `bond_kind`; replay must not use `bond_id` in the invitation key.
- Acceptance checks only **active** bonds for slot capacity; counting the sender's own pending request incorrectly rejected valid acceptances.
- Held-gift acceptance rechecks wallet freeze and invalidates with a closure notification when the sender is frozen.
- Termination invalidates pending requests, releases held funds, bumps participant bond versions and notifies the partner where legacy does.
- `LONGEST` rankings include day-0 active bonds and preserve legacy activation ordering before compaction.
- Milestone maintenance persists `bond_milestones`, grants the day-7 frame to both partners and emits level-up/reminder notifications.
