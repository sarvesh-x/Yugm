# D1 events routes

The shared D1 Worker now mounts the seven legacy `/api/events` handlers through both legacy mounts: `/api/events/*` and the older double-prefixed `/api/events/events/*`. The audit reports `/api/events` as `14 mounted / 0 missing`; overall coverage is `legacy 638 / d1 273 / matched 268 / missing 370`.

## Behavior preserved

- `POST /events` keeps the legacy auth → create limiter → Zod order, defaults and DTO shape. `title` is trimmed before persistence as the Mongoose schema did, and an invalid `roomId` becomes the same `400 "Invalid identifier"` the model cast produced. The `create` limiter is injected from the Worker binding and returns the legacy `429` and `Retry-After: 60`.
- `GET /events` keeps page/limit clamping, featured-first/event-date sorting, all filters, and the legacy `upcoming` override of `status`. The host is populated as a limited person DTO; participant IDs stay unpopulated.
- `GET /events/:eventId` populates host and participants with the same limited field set the legacy `.populate()` selected. The double-prefixed path returns the same event.
- `GET /events/user/me` returns unpopulated `hosting` and `joined` events, bounded to 50 each.
- `POST /events/:eventId/join` uses one conditional D1 insert for the `UPCOMING` and capacity checks, updates `updated_at` with the participant change, and classifies retries as already-joined, closed, missing or full in the legacy order. The host notification is non-fatal after the authoritative insert.
- `POST /events/:eventId/cancel` is host-only and returns the legacy `404` message. `POST /events/:eventId/leave` removes only the caller's participant row, timestamps the update like Mongoose `$pull`, and returns the unpopulated event. Detail and cancel keep the legacy cast error message `Invalid identifier`; join and leave keep the service-level `Invalid event ID`.

`0024_event_participants_unique.sql` adds the `(events_id, value)` unique key and a user lookup index so a concurrent join retry cannot create a duplicate participant row. A unique-key race is re-read and classified like the legacy retry.

## Boundary and remaining work

`0024` is added to the fresh-fixture migration sequence only. The recovered local database remains at `0019`; hosted D1 application through `0024` is still unverified. No hosted migration, data import, provision, deploy, credential change or MongoDB retirement was performed. Event join notifications are stored in D1 and eligible for the existing push job, but live FCM delivery and two-client Android acceptance remain open. The legacy event handlers do not publish Socket.IO events, so no D1 realtime emitter was added.
